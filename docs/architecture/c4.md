## Authorised worker update — 20 October 2026

[Approval record](../engineering/authorised-decisions-2026-10-20.md): generic Event Processor and separate Tracking Photo Worker replaced with Aquarium/Tracking/Advisor Async Workers. Each owns store access and outbox publication; photo processing is inside Tracking. Tracking History Store is not a shared event sink. Core writes commit synchronously; deferred advice/photo commands use one namespace with separate entities. Advisor retrieves history through owner API.

Affected source: systems.dsl, relationships.dsl, deployment.azure.dsl and views.dsl. The deployment view models three Function Apps on an existing shared-platform plan, with capacity/OS/runtime/Always On still requiring verification. Container view continues to exclude Observability. Foundry dependency is explicit, not model/provider selection approval.

The worker update initially preserved workspace.json; the subsequent service-view update regenerated it through Structurizr Lite. Existing SVG exports remain stale.

## Service-focused views — 20 October 2026

The combined Containers view is replaced by AquariumContainers, TrackingContainers and AdvisorContainers. Each includes its owner API/worker/stores, shared edge/messaging and necessary neighbour APIs, excluding Observability. AquariumOutbox, TrackingOutbox and AdvisorOutbox dynamic views explain transaction/relay boundaries without inventing separate outbox containers. This is a presentation refinement of accepted ADR-003/007/008/012; service ownership is unchanged.

## Parameter validation refinement

Accepted ADR-023 is reflected in the Tracking-to-Aquarium relationship, TrackingContainers description and RecordParameter/TrackingOutbox dynamic views: UI definition discovery, one trusted validation batch, no save on stale/unavailable rules, then local panel/outbox commit. ## Accepted shared data placement

ADR-024/005 update the logical Aquarium SQL node to Aquarium SQL Schema in shared ReferenceProjectsDb, and Tracking History Store to app-owned /tankId containers in shared Cosmos ReferenceProjects. Deployment nodes place physical SQL/Cosmos hosting, namespace and monitoring under shared platform; app data ownership remains explicit. Model identifiers and three service view keys are unchanged. Reload Lite to regenerate workspace/exports; live placement is not verified.

## Environment/hosting documentation refinement

ADR-025 accepts initial Local/dev only with Test/Production provisioning deferred. Generic Azure deployment view does not establish Test/Production resources exist. ADR-024 now accepts externally managed shared APIM/Blob account/PostgreSQL server hosting; the subsequent accepted Development hosting update reconciles physical deployment-node placement in Structurizr; runtime availability and access remain unverified. This documentation update does not add model elements, create environments or deploy platform resources.

## Accepted identity update

ADR-009 adds explicit Angular-to-External-ID PKCE acquisition, APIM metadata/signing-key dependency and independent API checks, plus CustomerIdentity dynamic view. Metadata/key retrieval does not imply an identity-provider round trip for every API request. Workload token/delegation configuration remains TBD and is not replaced with untrusted actor headers. Reload Lite to regenerate the workspace; static exports require separate refresh.

## Development hosting/ingress reconciliation

Accepted ADR-011/024/025/026 places separate API apps and worker Function Apps on shared Linux plan, APIM/shared Blob/PostgreSQL hosting under shared platform, and Angular on its intended Static Web Apps host. Azure deployment view is explicitly Development target only. Public backend access restrictions are conditional on verified addresses; no actual IPs/rules or private networking are implied. No initial Front Door/WAF. Config/secret dependencies are documented in ADR-027 rather than adding clutter to service container views. Reload Lite after source changes.

## Accepted code/technology labels

ADR-002/028/029 accept service-local layering, direct Cosmos SDK, .NET 10/C# 14/relational EF Core 10, Angular 22/strict TypeScript/Vitest and hybrid Local access. Canonical systems.dsl technology labels reflect approved majors without changing model IDs/views/ownership. Functions host/provider compatibility remains an explicit gate. Configuration operation policy lives in ADR-027; no refresh/rotation infrastructure is configured by this update.
