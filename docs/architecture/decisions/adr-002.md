# ADR-002: Proportionate Clean Architecture

Version: 0.2 | Date: 20 October 2026 | Status: Accepted

Owner/approver: human owner/architect. Evidence: owner agreed the four-layer/API-worker sharing proposal and requested this consolidated documentation update. See [approval record](../../engineering/authorised-decisions-2026-10-20.md).

## Context and options

The project demonstrates testable service boundaries without unnecessary abstraction. Alternatives were framework-coupled logic or excessive interfaces/projects. Select useful separation rather than boilerplate.

## Decision

Use Domain, Application, Infrastructure and API/Functions host roles within Aquarium, Tracking and Advisor.

- Domain contains business concepts/rules, independent of HTTP, Azure, ORM and database clients.
- Application orchestrates use cases/validation and defines narrowly scoped external-dependency interfaces; it depends on Domain.
- Infrastructure implements persistence, messaging and integrations; it depends on Application/Domain.
- API/Functions hosts adapt HTTP/triggers into Application use cases and perform composition. Host wiring may reference Infrastructure; business logic does not depend on host SDKs.
- A service's API and Async Worker reuse its Application/Domain code; do not duplicate business rules in triggers.
- Cross-service sharing is limited to small technical utilities, not domain entities or persistence models.
- Use separate projects where useful; do not require an interface or repository wrapper for every class.

## Verification and remaining work

Review compile/project dependency directions and test core rules without Azure. Exact project names, folder boundaries and commands are implementation-readiness work. This decision does not approve broad unrelated refactoring or application implementation.
