# ADR-025: Local and Development initially; release environments deferred

Version: 0.1 | Date: 20 October 2026 | Status: Accepted

Owner/approver: human owner/architect. Evidence: “I agree to begin with Local and Development only, deferring Test and Production provisioning until release preparation. Update docs”.

## Context and options

Establishing all environments immediately adds hosting cost and setup. Alternatives were immediate Local/Dev/Test/Production provision or initially Local plus shared dev. The owner selected the latter.

## Decision

Initially establish Local for development/repeatable automated tests and Development (dev) for deployed integration tests/demonstrations. Use synthetic data and development identities separate from eventual production. Compatible emulators/test doubles may be supplemented by authorised dev Azure dependencies.

Defer dedicated Test and Production provisioning until release preparation. Run meaningful automated tests from the start; a dedicated Test environment is not a prerequisite for test execution.

## Platform dependency

Shared platform updates/deployment are separately owner-requested work outside Parameter Pilot's agentic application process. Verify required shared dev hosting exists before agentic implementation starts. App pipelines reference existing hosting, never silently create/modify shared SKUs or platform policy.

## Consequences and verification

Stage 1 must demonstrate reproducible local setup, usable dev access, isolated synthetic data/configuration and appropriate permissions. Do not create Test/Production resources or imply production readiness. Before public release resolve those environments' topology, isolation, costs, security, promotion and recovery.

No exact tier, deployment workflow authority, numeric NFR, spending or platform deployment is approved by this ADR. See ADR-022/024 and [environment specification](../../development/environments.md).
