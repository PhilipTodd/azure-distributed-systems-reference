# ADR-029: Hybrid Local dependencies and individual developer identity

Version: 0.2 | Date: 21 October 2026 | Status: Accepted approach; concrete tools/access pending

Owner/approver: human owner/architect. Evidence: owner separately accepted individual Entra developer identities and hybrid local dependencies, followed by documentation-update request.

## Decision

- Developers use their own Microsoft Entra identities with approved scoped Development access, through an approved developer login such as Azure CLI or Visual Studio.
- No shared developer accounts or copied deployed-workload credentials. Broader migration/administration privileges remain separate.
- This is developer access to Azure resources, not aquarium-owner sign-in; customer UI remains External ID under ADR-009.
- Run service code and practical database/storage dependencies locally; compatible emulators where they meet required behaviour.
- Deterministic test doubles support unit tests and repeatable failures.
- Use authorised dev Azure resources for identity/features not represented adequately locally, and real Azure integration checks before accepting cloud-dependent behaviour.
- An in-memory substitute does not prove broker delivery/security/transaction semantics.
- Unavoidable local secrets remain User Secrets/equivalent untracked settings; no production identity/data or credentials.

## Remaining details and verification

Exact emulators/images/tools/versions, Azure dependency endpoints, developer roles/scopes, credential selection and test commands remain TBD. Verify a fresh setup, synthetic fixtures, allowed/denied dev access and emulator/cloud feature differences. Do not grant broad subscriptions rights merely for developer convenience.

Platform is separately provisioned and initial scope Local/dev only. Acceptance does not configure developer machines, sign anyone in or grant access.

## Traceability

ADR-009/024/025/027; [Local design](../../development/local-development.md), NFR-007/009. No implementation/deployment claimed.

## Minimum Stage 2 Local setup — accepted 21 October 2026

DEV-03: minimum Stage 2 Local setup runs Angular UI and Aquarium/Tracking APIs directly through development tooling. Docker Compose starts SQL Server Developer and Cosmos DB NoSQL emulator containers; use a small repeatable synthetic seed set. Actual Development External ID supports customer authentication/OBO. Select/pin supported compatible container/tool versions after verification; no preview assumption or floating latest pin. Local certificate and secrets follow ID-15/ADR-027.

Emulator/container results are not proof of Azure parity. Verify required operation support, including same-container/partition transactions, and real Development identity/permissions/cloud behaviour. If a required operation is unsupported locally, use the approved Development dependency for that check rather than building an inaccurate substitute. No unapproved resource creation/spend implied.

Advisor/PostgreSQL/photo dependencies wait for their stages. Add Service Bus and workers when the authorised implementation slice requires them; preserve core synchronous transaction/outbox design and do not fabricate broker-delivery evidence. Docker Compose manages dependencies, not a requirement to containerise local UI/APIs. No Compose file, dependencies, seeds, projects or resources created in this documentation update.
