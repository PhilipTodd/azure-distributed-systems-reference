# ADR-007: Synchronous core writes and transactional outboxes

Version: 0.2 | Date: 20 October 2026 | Status: Accepted

Owner/approver: human owner/architect. Evidence: [20 October approval record](../../engineering/authorised-decisions-2026-10-20.md).

## Context and alternatives

The project demonstrates large-system architecture with explicit operational tradeoffs despite modest expected traffic. Alternatives considered: a generic multi-store processor, queueing every write, direct write-then-publish, or independently hosted service workers.

## Decision

Synchronously commit tank updates, measurements, maintenance and observations to the owner's store together with a local outbox. Return success after durable commit, not after queue acceptance. The owner's worker publishes the persisted outbox asynchronously. SQL/PostgreSQL use local transactions; Cosmos uses one container/logical partition for state/idempotency/outbox. Consumers deduplicate and commit inbox/state together where possible.

## Consequences and verification

Test broker outage after commit, relay crash after send, duplicate/stale delivery, poison handling and replay. No exactly-once claim. Async advice/photo APIs return 202 only after durable job/work registration. Bulk async ingestion is an optional future design, not blanket queued CRUD.
