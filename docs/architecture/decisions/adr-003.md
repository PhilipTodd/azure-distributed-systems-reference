# ADR-003: Service-owned stores and authorised context APIs

Version: 0.3 | Date: 20 October 2026 | Status: Accepted

Owner/approver: human owner/architect. Evidence: [20 October approval record](../../engineering/authorised-decisions-2026-10-20.md).

## Context and alternatives

The project demonstrates large-system architecture with explicit operational tradeoffs despite modest expected traffic. Alternatives considered: a generic multi-store processor, queueing every write, direct write-then-publish, or independently hosted service workers.

## Decision

APIs and workers access only their own stores: Aquarium SQL, Tracking Cosmos/Blob and Advisor PostgreSQL. Advisor obtains history via Tracking API and profile/entitlement via Aquarium API. Tracking Cosmos is not a shared event/telemetry database. A future TankCreated consumer may write a Tracking-owned timeline projection only after a concrete product requirement is approved.

## Consequences and verification

Verify workload and actor/resource authorisation, owner-only data-plane roles and no cross-service store credentials. Owner APIs introduce dependency availability; detailed delegation/freshness settings remain open.
