# ADR-008: One Service Bus namespace and routed commands/events

Version: 0.2 | Date: 20 October 2026 | Status: Accepted

Owner/approver: human owner/architect. Evidence: [20 October approval record](../../engineering/authorised-decisions-2026-10-20.md).

## Context and alternatives

The project demonstrates large-system architecture with explicit operational tradeoffs despite modest expected traffic. Alternatives considered: a generic multi-store processor, queueing every write, direct write-then-publish, or independently hosted service workers.

## Decision

Use one Service Bus namespace shared by the application's APIs/workers, with separate service-addressed command queues and publishing-context event topics with consumer-specific filtered subscriptions. Workers receive relevant work, not every message. Copies within one queue/subscription compete; separate subscriptions enable fan-out. Use at-least-once handling, idempotency, bounded retries, DLQs, correlation and audited replay; sessions only when required.

## Consequences and verification

Detailed entity names, settings, schemas and SKU remain to be approved. Selected tier must support required topics/subscriptions. Do not deploy empty consumers/projections just for demonstration. Dapr remains deferred as in the earlier proposal; adoption needs separate approval.
