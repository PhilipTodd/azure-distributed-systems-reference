# ADR-018: GitHub Actions as sole Parameter Pilot CI/CD authority

Version: 0.2 | Date: 20 October 2026 | Status: Accepted

Owner/approver: human owner/architect. Evidence: “I agree to GitHub Actions as Parameter Pilot's sole CI/CD authority and migrating/retiring existing Azure Devops pipelines. Update docs”.

## Context and options

Parameter Pilot intends GitHub-based delivery, but infra/pipelines contains Azure DevOps deployment definitions. Alternatives were Azure DevOps, dual providers, or one GitHub Actions authority. Multiple active deployers risk conflicting application/environment changes.

## Decision

- GitHub Actions is the sole target CI/CD authority for Parameter Pilot builds, PR checks, security checks, image publishing and application deployments.
- Build/push container images to approved shared ACR; deploy by immutable identity/digest under the approved release design.
- Use GitHub OIDC federation for Azure access at least-privilege application/child-resource scopes; untrusted PR jobs receive no deployment credentials.
- Human approval is required before merge. Exact checks/rulesets, reviewers, credentials, environments and deployment approvals require verified configuration.
- Initially target Development only for Azure deployment; run local/automated tests from the start. Do not activate Test/Production provisioning until release preparation (ADR-025).
- Shared platform Bicep/deployment is separately owner-managed work outside the Parameter Pilot application process. This decision does not govern/change the platform repository's pipeline.

## Migration and retirement

Inventory existing infra/pipelines/deploy-infrastructure.yml and deploy-web.yml, their externally configured definitions/triggers, service connections, permissions and secrets. Preserve current behaviour until equivalent GitHub workflows are verified.

Implement and validate replacement build/check/image/dev-deploy paths without concurrent competing deployments. Agree cutover; stop legacy deployment triggers/definitions before enabling the replacement as the active deployer for that target. Retire legacy YAML/definitions after verified cutover, retaining audit/history and revoking obsolete application-specific credentials only after dependency review.

These are planned implementation tasks. This documentation change does not create workflows, delete/disable pipelines, alter access, deploy resources or mark migration complete.

## Verification and consequences

Prove required PR gates, isolated OIDC access, image push/pull, dev deployment/smoke checks, migration/recovery, traceability and lack of active competing deployers. Actual commands/check names and repository/environment protections remain to be configured and tested.
