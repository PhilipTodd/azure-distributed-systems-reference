# ADR-030: Automated testing and browser verification

Version: 0.1 | Date: 20 October 2026 | Status: Accepted approach; setup/verification pending

Approver: human owner/architect. Evidence: owner agreed the testing strategy, subsequently agreed Playwright and its proposed scope, then requested documentation updates.

## Decision

Adopt unit, component, integration, API/event contract, security and critical end-to-end verification proportionate to changed behaviour and risk. Use xUnit for backend tests, Vitest/Angular TestBed for frontend unit/component tests, and Playwright Test with TypeScript for browser tests.

Run critical Chromium journeys on pull requests as features arrive; run broader Firefox/WebKit checks before releases. Use synthetic data and controlled accounts; exclude generated authentication state from source and protect sensitive reports/traces/screenshots.

Applicable builds, static analysis and tests must pass before merge. Failed required checks block merge. Report unavailable/skipped verification honestly. No blanket coverage percentage initially; add versioned AI evaluations in the AI stage.

## Consequences and readiness

Integration tests must establish transaction/outbox, broker and security behaviour with suitable real dependencies; doubles alone cannot establish Azure guarantees. Keep the browser suite small and focused to limit execution cost and flaky tests.

Exact compatible versions, backend assertion library/licensing, workflow/check names, test identities/fixtures and report retention/access configuration remain pending. This decision does not establish that runnable projects, tests or CI enforcement exist.
