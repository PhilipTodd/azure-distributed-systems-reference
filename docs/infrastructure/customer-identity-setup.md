Environment input: `infra/bicep/environments/dev/customer-identity.json`. Bootstrap: `scripts/bootstrap-customer-identity.py`, default plan-only. Applying requires --tenant <verified-customer-tenant-id> --apply and the appropriate authenticated customer-tenant administrative session. The script refuses the known workforce tenant, checks the customer directory's CIAM type/domain, stops on ambiguous/unrecorded existing objects, saves only nonsecret IDs and verifies registration configuration by read-back.

## Certificates and verification

`scripts/bootstrap-obo-certificates.py --apply` created the Development certificate `tracking-obo-dev` in existing `kv-adt-tracking-dev`, RSA3072/self-signed/client authentication with 12-month validity, and separate Local certificate in Windows CurrentUser/My with a non-exportable CNG private key. The private Development key was generated in the vault; the Local key was not exported. Only two public certificates were registered on Tracking, with no client secrets, and credential read-back passed. The temporary owner Certificates Officer grant was removed and independently verified absent. [Certificate metadata](evidence/obo-certificates-2026-11-03.json) contains public certificates/identifiers only.

The local helper explicitly loads Windows certificate modules in a noninteractive child session; an initial missing Cert: provider was corrected. Key Vault create returns an operation rather than the certificate bundle, so the coordinator now reads the public certificate bundle after creation. Interrupted setup can reuse recorded/existing keys without exporting private material.

Rotation remains operator controlled: create/register a new public credential alongside the old one; update the exact Development secret version/reference or Local thumbprint, restart the affected app, verify OBO and then explicitly revoke the old registration. Do not assume overlap/restart alone proves all active connections changed. No auto-renewal policy was enabled. Certificate expiry/renewal monitoring and actual runtime startup handling must be carried into Step 7/application implementation.
